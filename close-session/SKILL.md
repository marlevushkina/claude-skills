# Закрыть сессию

Сначала определи, какие шаги применимы к этой сессии: не каждая сессия трогала код или внешние сервисы.
Внешние действия (push, деплой, отправка сообщений) и необратимые операции — только с явного подтверждения
человека. Не создавай лишние файлы ради ритуала.

## 0. Инвентаризация (молча, для себя)

Пройди по сессии и выпиши:

- исходный запрос и что в итоге сделано;
- какие **внешние артефакты** трогали: таблицы, документы, сервисы, боты, сервер — и в каком они состоянии
  (задеплоено? проверено вживую?);
- какие **файлы репозитория** создала или изменила именно эта сессия (не путать с чужими правками в рабочем дереве);
- что осталось: хвосты, «сделаем потом», вопросы без ответа;
- **где человек поправлял, переспрашивал, злился, отменял**: неверные допущения, лишние вопросы, не тот формат,
  повтор уже известного, слишком длинно или коротко. Это сырьё для шага 4.

## 1. Собрать артефакты

1. Незавершённые правки — довести или откатить. Полуправок в рабочем дереве не оставлять.
2. Внешние артефакты — проверить состояние **по факту** (перечитать таблицу, лог, статус деплоя), а не по памяти.
   Если результат живёт только вне репозитория, оставить в репо заметку или скрипт, как его найти и повторить.
3. **LOG.md проекта** (в папке задачи; если нет — создать): запись сверху `## YYYY-MM-DD — <тема>` с полями
   Did / Decided / Artifacts / Remaining / Open questions. **Remaining — главное поле**: его читает следующая
   сессия, поэтому пункты пишутся самодостаточно (пути файлов, ID, что считать готовым).
4. **Память агента** (например, auto-memory Claude Code): обновить или создать заметки о состоянии задачи
   и решениях человека, которых не видно из кода, и о том, как человек любит работать (см. шаг 4).
   Дубликаты не плодить — обновлять существующую заметку.
5. Документацию репозитория — если поменялось устройство (индексы, карты файлов, спеки).

## 2. Закоммититься

1. `git status` — включать **только файлы этой сессии**. Чужие незакоммиченные правки не трогать:
   то, что файл виден в `git status`, не делает его частью сессии.
2. Скан перед коммитом: секреты, токены, `.env`, персональные данные людей. Сомнение — не коммитить файл, спросить.
3. Коммит с осмысленным сообщением.
4. `git pull --rebase --autostash` перед push.
5. Push — по правилам твоего репозитория; по умолчанию спросить одной строкой «запушить N коммитов?».

## 3. Завести задачи на хвосты

Каждый хвост, который **не сделать за минуту прямо сейчас**, превращается в отдельную задачу:

- если клиент умеет запускать новые сессии (например, Claude Code desktop) — отдельная сессия с заголовком-глаголом
  и **самодостаточным** промптом: пути файлов, ID, что считать готовым, без ссылок на «этот разговор»;
- если нет — пункт в `Remaining` LOG.md в том же самодостаточном виде.

**Модель для новой сессии — минимально достаточная, явно.** Новая сессия часто наследует модель родителя,
и дорогая модель сжигает лимиты на механических задачах. Простые сообщения, сверки, чек-листы — самая лёгкая
модель; код и разбор данных — средняя; самая сильная — только когда задача реально требует, и это сказано человеку.
Первой строкой промпта пиши, какая модель нужна.

Не заводить: то, что человек явно отложил без срока (записать в LOG как отложенное), и чужую работу
(её — одной строкой «сказать X»).

## 4. Не бесить тем же (бесить новым)

Пройди по списку раздражений из инвентаризации и для каждого сделай **одно** из:

- **правка SKILL.md** использованного скилла — если раздражение специфично для этого скилла
  (в «не делать», в порядок шагов, в источники);
- **правка инструкции проекта** (CLAUDE.md / AGENTS.md) — если это общее правило работы; редко, только повторяющееся;
- **заметка в память** — если правило про то, как человек любит работать, а не про конкретный скилл.
  С причиной («почему») и тем, как применять.

Правила шага: одно раздражение — одно место; перед записью проверить, нет ли уже такой строки (обновить, не дублировать);
показать человеку список правок в 1–3 строки. Если раздражений не было — так и сказать, ничего не выдумывать.

## 5. Рассказать по-человечески

Финальное сообщение, 5–10 предложений, без списков файлов и техжаргона (файлы — в LOG):

1. что было исходной задачей и что сделано;
2. **зачем это было**: что теперь по-другому в работе человека;
3. что не сделали и почему (или что отложили по его слову);
4. какие задачи заведены и что нужно от человека — по одному глаголу на пункт;
5. если пушили или деплоили — куда, одной строкой.

Тон: как коллеге в конце дня, не отчёт. Не хвалиться и не извиняться дважды за одно и то же.

## Чек-лист перед финальным сообщением

- [ ] Внешние артефакты проверены по факту, ссылки и ID есть в LOG
- [ ] LOG.md дописан сверху; Remaining самодостаточен
- [ ] Память обновлена, без дублей
- [ ] Коммит только своих файлов, скан секретов пройден
- [ ] Хвосты заведены задачами или записаны в Remaining; у каждой задачи указана модель
- [ ] Раздражения разобраны: скилл / инструкция / память
- [ ] Финальное сообщение человеческое, с «зачем»
